# 收窄 ProTableActions 布局配置

原有组件把数量、方向和网格配置混合在 `layout` 中，并针对不同排列维护宽度退化分支。本次将 `layout` 收窄为 `maxRows` 与 `maxColumns`，通过命名明确行列均为上限，移除 `direction`，固定按行填充；数量配置提升至顶层并改名为 `maxVisibleCount`，且同时传入时以 `layout` 为准，以减少配置组合和维护成本。本记录替代 ADR-0001。

网格保留容量包含更多入口的规则，只有操作超过容量时才将最后一个槽位用于更多入口。单列排列通过 `maxColumns: 1` 表达。未提供网格且 `maxVisibleCount` 未传或为 0 时，全部业务操作收入菜单；默认入口统一使用本地化的“更多”与图标。

数量模式将 `maxVisibleCount` 作为外露数量上限，仅支持数字，移除 `'all'`。空间不足时，短文案优先完整显示，长文案省略；若外露按钮达不到约定的最小可见宽度，则从末尾依次将操作收入菜单并重新分配，最终可退化为整组收纳。菜单保留原操作顺序。

已确认：长文案至少保留 `3em` 文字空间（包含省略号），图标、间距、边框另计；天然短于此阈值的文案只需完整显示。原先的 `2em` 可能只显示一个汉字和省略号，因此提高到 `3em` 以更早触发收纳。自定义更多入口最大宽度受内容区约束，普通文字省略，无法省略的自定义内容裁剪，极窄时仍遵守容器宽度。继续仅在显式 `width` 或 `style.width` 下启用宽度约束，`width` 优先，跟随表格列宽时使用 `width="100%"`。

网格与数量模式共用阈值判断、从末尾逐项收纳、整组收纳和恢复流程，宽度分配分别使用等宽列与短文案优先算法。`maxRows`、`maxColumns` 均为上限；网格开始收纳后允许减少实际列数，并在行数上限内重新按行填充，使剩余操作获得更多宽度。只减少操作数量而固定列数无法释放列宽，因此接受退化时按钮位置变化的代价。

更多入口是最终入口，不参与业务文字阈值判断。即使单列业务按钮因阈值不足全部收纳，入口自身也可能放不下；此时依次省略入口文字、裁剪内容，始终受内容区宽度约束，不递归生成更多入口。
